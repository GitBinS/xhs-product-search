# xhs-product-collect · 小红书商品 / 店铺公开数据采集

从粘贴的链接或 ID 采集小红书**公开页面**数据，输出结构化 JSON / Markdown，可选落盘为 .md 笔记。
免登录、免 Cookie、免签名、纯 Python 标准库（无 pip 依赖）。

## 一条命令

```bash
python3 <本skill目录>/scripts/collect.py "<商品链接|商品ID|店铺链接|店铺ID|分享文案>"
```

拿不准用什么格式时，**默认的 stdout JSON 模式最通用**；要人读的排版加 `--md`；要存成笔记加 `--save "<目录>"`。

| 场景 | 命令 |
|---|---|
| 采商品（JSON 到 stdout） | `python3 <skill目录>/scripts/collect.py "https://www.xiaohongshu.com/goods-detail/<商品ID>"` |
| 采商品（Markdown 到 stdout） | `python3 <skill目录>/scripts/collect.py "<链接或ID>" --md` |
| 采商品并落盘笔记 | `python3 <skill目录>/scripts/collect.py "<链接或ID>" --save "./商品采集"` |
| 采店铺 | `python3 <skill目录>/scripts/collect.py "https://www.xiaohongshu.com/shop/<sellerId>"` |
| 强制按店铺采集 | 上面命令加 `--shop` |
| 引擎自检（不发网络请求） | `python3 <skill目录>/scripts/collect.py --selftest` |

> Windows 环境把 `python3` 换成 `python`。

## 输入识别

| 输入形态 | 行为 |
|---|---|
| 完整商品链接（`…/goods-detail/<ID>`）或裸商品 ID（16–32 位十六进制） | 商品采集 |
| 商品分享短链（xhslink.com 等） | 自动逐跳展开（≤6 跳）后再识别；展开到登录页 = 口令失效，会提示改用完整链接或裸 ID |
| 带文字的分享文案 | 先从文案里提取链接/ID，再按上两行判断 |
| 店铺链接（`…/shop/<sellerId>`） | 自动转店铺采集 |
| 笔记链接（explore / discovery）、账号主页链接 | **明确报错**并说明原因（不猜、不硬采） |
| 纯文字、无任何链接 | 报「里面没有 http 链接（只粘了文字？）」 |

- `--shop` 模式：裸 ID 按**店铺 ID** 处理（强制按店铺采集）；
- 默认模式：裸 ID 按**商品 ID** 处理。
- 认不出目标时，会把「究竟认到了什么」的诊断信息（why）原样返回，便于用户修正输入。

## 字段口径

stdout JSON 顶层结构（中文键名原样保留）：

```
{ ok, kind: "item"|"shop", itemId, 链接, sellerId, archive{...}, track{...}, extra{...},
  warnings[], 抓取时间, raw }        # 失败时另有 error（且 stdout 的 JSON 同时给出错误对象）
```

| 分组 | 语义 | 键（商品采集） |
|---|---|---|
| **archive** | 固定 / 低频字段（一品一行） | 商品标题、商品售价、对标到手价、发货地、店铺评分、上架天数、上架日期、来源、SKU数、选中SKU、店铺链接、店铺名、店铺总销量、粉丝数、商品角标 |
| **track** | 变动字段（一天一行，目前仅「商品销量」） | 商品销量 |
| **extra** | 采集规格之外的字段，原样保留供人查看 | 运费、发货时效、服务标签、商品标签、促销标签、库存状态、已售原文、已售是下界、已售口径、上架来源、seller_id、item_id 等 |
| **warnings** | 非阻断提示（数据可用性说明） | 「已售是下界」= 原文形如「已售1.5万+」，是下限不是精确值；「SKU 级」= 销量只有当前选中 SKU 的口径 |

**「已售」双口径说明**：

| 口径 | 含义 | 何时出现 |
|---|---|---|
| 商品级（店铺页） | 店铺页给出的商品级销量 | 该商品出现在店铺首页可见列表时（覆盖 API 值） |
| SKU级（API） | 仅当前选中 SKU 的销量，非商品累计，口径有偏差，仅供参考 | 该品不在店铺首页可见列表时 |

两种口径都可能带下界标记（`已售是下界 = true`，说明销量是「X+」这样的下限值）。

店铺采集（kind=shop）另含 `shop{店铺名, seller_id, 店铺总销量, 粉丝数, 好评率, 发货时效}` 与 `products[]`（首页可见商品列表，含标题、价格、已售、上架日期、上架天数、角标）。

## 已知限制

1. **「开店天数」网页端采不到**（该字段只在 App 的「店铺详情」页有）→ 输出中留空，需要人工补填；脚本不会猜、不会编。
2. **非官方公开接口**，可能随平台改版失效。报错时把 stderr 原文给用户，**禁止瞎猜字段或编造数据**。
3. **店铺页解析对改版脆弱**：商品列表由 DOM 卡片 + 内嵌 JSON 双侧解析后按标题配对，条数不一致时会给出「⚠ 两侧条数不一致」警告 → 此时列表数据需人工复核。
4. **需能直连小红书的网络环境**；连不上时以退出码 3 明确报告（不会静默失败）。
5. 短链展开后被跳到登录页 = 该口令在网页端拿不到商品地址（可能已失效或只认 App）→ 改用完整链接或裸 ID。

## 退出码

| 码 | 含义 |
|---|---|
| 0 | 成功 |
| 1 | 解析失败（认不出链接/ID）或参数用法错误 |
| 2 | 采集失败（接口报错、返回非 JSON、店铺页无数据等） |
| 3 | 网络失败（超时、连接失败） |
| 4 | 文件保存失败（`--save` 时） |

失败时：stdout 为 JSON 失败对象；stderr 为原因原文（含具体诊断），退出码区分类型。

## 频控纪律

- 同一商品两次采集间隔建议 ≥ 数小时（销量是低频变动数据，采太密意义不大）；
- 批量采集时逐条间隔 ≥ 3–5 秒；
- 单次会话采集总量 ≤ 20 条。

## 合规边界

- 只采集**公开页面**数据：无登录态、无 Cookie、无签名、不绕任何风控机制；
- 不采集任何个人信息；
- 数据仅作选品参考，请遵守平台服务条款，勿用于骚扰、批量爬取或商业侵权场景。
